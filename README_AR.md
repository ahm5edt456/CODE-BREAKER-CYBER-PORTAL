# CODE BREAKER: CYBER PORTAL — Campaign

ثلاث مراحل متتالية، في كل مرحلة بوابتان وتحدّيان أصعب من السابق. الواجهة داخل المتاهة والمحرر أصبحت بنفس أسلوب قائمة Cyber Portal، باستخدام pygame-ce وpygame_gui.

## التثبيت والتشغيل

على Fedora / Linux افتح الطرفية داخل مجلد اللعبة:

```bash
bash setup.sh
bash start.sh
```

التثبيت مرة واحدة في بيئة `.venv_portal` مستقلة، ويحتاج إنترنت لتثبيت المكتبات فقط. على Windows شغّل setup.bat أولاً ثم start.bat. تشغيل C++ يتطلب g++، وJava تتطلب javac وjava في PATH.

## الاستكشاف والانتقال بين المراحل

1. تجوّل في المتاهة للوصول إلى التحدّي الأول.
2. بعد حله، انتقل إلى التحدّي الثاني الموجود في منطقة أخرى بعيدة.
3. بمجرد حلّ آخر تحدٍّ تظهر شاشة نجاح قصيرة، ثم تبدأ المرحلة التالية تلقائياً بعد نحو ثانية واحدة. يمكن الضغط على CONTINUE أو Enter لتجاوز الانتظار.
4. لا توجد عودة إلى نقطة البداية، ولا حاجة للوصول إلى مخرج معيّن لإنهاء المرحلة.

تُختار مواقع التحدّيات في مناطق مختلفة بعيداً عن زاوية البداية، مع التحقق من أن التحدّي الأول قابل للوصول دون المرور بالبوابة الثانية، وأن الوصول إلى الثاني ممكن بعد حل الأول. تُحل الأسئلة حسب أرقامها للحفاظ على تدرّج الصعوبة.

بعد آخر تحدٍّ في المرحلة الثالثة تنتهي الحملة بالفوز، وتظهر خانة الاسم لحفظ النتيجة في High Scores. الخسارة أيضاً تعرض خانة الاسم.

لكل مرحلة 120 ثانية. يبدأ عدّاد جديد في المرحلة التالية وتبقى القلوب المتبقية كما هي. الحد الأقصى لزمن اللعب الفعلي ست دقائق، دون احتساب الإيقاف وشاشات الانتقال القصيرة. نفاد الوقت أو القلوب ينهي الحملة.

## بنك الأسئلة العشوائي وتدرّج الصعوبة

بنك الأسئلة يحتوي عشرة أنواع، وتختار كل لعبة ستة أنواع دون تكرار داخل الجولة، موزّعة على ثلاث مراحل:

- البداية: العمليات الحسابية، دمج النصوص، الفهرسة، والمقارنات. تختار المرحلة الأولى نوعين منها.
- المتوسط: حدود الحلقات، التجميع، وعدّ العناصر التي تحقق شرطاً. تختار المرحلة الثانية نوعين منها.
- المتقدم: الدوال مع الشروط، تحويل القيم الموجبة، والحلقات المتداخلة. تختار المرحلة الثالثة نوعين منها.

تُرتّب الأنواع المختارة حسب صعوبتها، وتُغيّر القيم الرقمية والنصوص أيضاً. يدعم كل نوع Python وJava وC++، وخياري Debugging وComplete Code. تبقى الحملة ثلاث مراحل وستة تحدّيات، وليست عشرة تحدّيات في الجولة الواحدة.

في Complete Code يُحدَّد تعليق TODO في السطر الناقص تلقائياً عند الفتح. اكتب الكود مكانه مباشرة؛ تبقى المسافة البادئة محفوظة. Reset يعيد هذا التحديد. مسودة التعديل تبقى عند الرجوع للسؤال أثناء الجولة.

## الإعدادات

نوع المشكلة فقط: Debugging لإصلاح الخطأ، أو Complete Code لإكمال السطر الناقص، مع خيار تشغيل الصوت أو كتمه. لا يوجد اختيار يدوي للمستوى أو الجولة، ولا يطلب الاسم قبل اللعب.

## الواجهة والتحكم

أُزيلت نقاط التوجيه أمام BYTE وأثر الخلايا التي مرّ عليها. قطع الطاقة الذهبية قابلة للجمع وتضيف 10 نقاط؛ وهي مختلفة عن نقاط التوجيه المحذوفة.

يوجد شريط يوضح المراحل الثلاث، وعدد التحدّيات المكتملة والوقت والقلوب والنقاط. تعرض لوحة المهمة البوابات وحالتها، وتُظهر أن حل آخر تحدٍّ ينقل اللاعب تلقائياً إلى المرحلة التالية. توجد حركة أنعم للشخصية، ونبض للبوابات، وجزيئات عند النجاح، وشاشة انتقال بين المراحل.

- القائمة: الأسهم للتنقل، Enter للاختيار، Tab وShift+Tab للتنقل، Esc للرجوع. الماوس متاح أيضاً.
- اللعب: WASD أو الأسهم للحركة، Space للاندفاعة، E للتحدّي. تفتح نافذة التحدّي تلقائياً عند الاقتراب من بوابة أثناء الحركة.
- P أو Esc أثناء التنقل يفتح الإيقاف المؤقت. زر PAUSE يعمل في المتاهة والمحرر عندما لا يكون الكود قيد التشغيل. لا يُخصم وقت أثناء الإيقاف أو شاشة الانتقال. Enter يستأنف، ويمكن التنقل بين زري الإيقاف بالأسهم أو Tab.
- المحرر: F5 أو Run لتشغيل الكود مجاناً، F6 أو Submit لإرسال الحل. الإرسال الخاطئ يخصم قلباً؛ Run لا يخصم قلباً. F1 للتلميح، Ctrl+R لإعادة الكود، Esc أو Back للرجوع. عجلة الفأرة تمرر الناتج والأخطاء.
- F11 لتبديل ملء الشاشة. يفضل عرض 1280×720 أو أكبر.

## النقاط والاسم

كل حل صحيح: 100 نقطة، و25 إضافية إن لم يُستخدم التلميح، ومكافأة سرعة من 0 إلى 100 نقطة. الطاقة: 10 نقاط للقطعة، ويضاف الوقت المتبقي عند إنهاء كل مرحلة. النتائج محلية داخل مجلد اللعبة في `data/dashboard.json`. يُنشأ الملف تلقائياً عند التشغيل، وتُحفظ النتيجة بعد كتابة الاسم والضغط على SAVE SCORE، وتُحمّل النتائج عند التشغيل التالي. لا تتم قراءة ملفات نتائج قديمة أو استيرادها. حذف `data/dashboard.json` يبدأ لوحة جديدة فارغة، حتى إن حُذف الملف أثناء تشغيل اللعبة؛ والحفظ التالي يقرأ الملف الحالي بدلاً من دمج نتائج الذاكرة القديمة.

بعد نهاية الحملة اكتب الاسم ثم Enter أو SAVE SCORE. الاسم حتى 16 حرفاً، وBackspace للتعديل، وEsc لتخطي الحفظ. لا تُحفظ نتيجة باسم تلقائي، ولا يطلب الاسم بين المراحل.

## ملفات التنفيذ والاختبار

- main.py يشغّل CampaignGame في campaign.py.
- challenge_placement.py يختار مواقع التحدّيات المتباعدة ويتحقق من إمكانية الوصول إليها.
- campaign_questions.py يحتوي بنك الأنواع العشرة واختيار ستة منها عشوائياً.
- portal_ui.py يحتوي قائمة Cyber Portal والعناصر المشتركة.
- editor_support.py يحتوي تحديد النص والنقر والتمرير والحافظة داخل محرر الكود.
- game.py وengine.py يحتويان منطق اللعب الأساسي.
- assets/theme.json يحدد مظهر عناصر pygame_gui.

بعد التثبيت:

```bash
.venv_portal/bin/python test_campaign.py
.venv_portal/bin/python test_portal.py
.venv_portal/bin/python test_game.py
```

اختُبرت Python وC++ في بيئة التطوير. Java تحتاج إلى تجربة على جهاز فيه JDK. اختبارات الواجهات تستخدم SDL dummy؛ جرّب الصوت وملء الشاشة على جهاز العرض. الصور المرفقة من النسخة الحالية، ولا تتضمن الحزمة نتائج اختبار محفوظة.

التقييم يقارن الناتج الفعلي بالناتج المرجعي، والأسئلة ببيانات ثابتة داخل كل محاولة. التشغيل له مهلة وحدود على العمليات والناتج، لكنه ليس صندوقاً أمنياً لخدمة عامة؛ هذه النسخة للعرض المحلي بإشراف.

## ملف Dashboard JSON

الملف `data/dashboard.json` عبارة عن قائمة JSON تحتوي أعلى 30 نتيجة. كل سجل يتضمن الاسم والنقاط والوقت والدقة واللغة ونوع التحدّي وحالة الفوز والمراحل المكتملة، مع عدد المشكلات المحلولة والمحاولات والطاقة والقلوب المتبقية وتاريخ الحفظ `saved_at` بتوقيت UTC.

الأسماء تدعم UTF-8، بما فيها الأسماء العربية. يتم استبدال الملف بعد اكتمال كتابة النسخة الجديدة، حتى يبقى الحفظ السابق سليماً إذا فشلت الكتابة. إذا كان JSON تالفاً لا يُستبدل بنتائج فارغة؛ أصلح الملف ثم أعد الحفظ. عند تحديث اللعبة أو نقلها، احتفظ بملف `data/dashboard.json` وانقله إلى النسخة الجديدة. يمكن إفراغ لوحة النتائج يدوياً بجعل محتوى الملف `[]` بعد إغلاق اللعبة.

اختبار الحفظ المستقل:

```bash
.venv_portal/bin/python test_score_store.py
```

## مكافأة السرعة والاسم المتكرر

يبدأ عدّاد حلّ كل سؤال عند فتحه للمرة الأولى. مكافأة السرعة = `max(0, 100 - floor(ثواني الحل × 2))`: حل خلال 10 ثوانٍ يمنح 80 نقطة سرعة، و30 ثانية تمنح 40، وبعد 50 ثانية تصبح مكافأة السرعة صفراً؛ تبقى نقاط الحل الأساسية كاملة.

يتوقف عدّاد مكافأة السرعة أثناء الإيقاف المؤقت وتشغيل/ترجمة الكود. إغلاق السؤال والعودة إليه لا يعيد العداد من الصفر، ويستمر احتساب الوقت خارج نافذته بعد فتحه أول مرة. وقت التنقّل قبل فتح السؤال لا يدخل في مكافأة الحل. يبقى استعمال التلميح محفوظاً عند الرجوع للسؤال، فلا يمكن استعادة مكافأة عدم استخدامه بإعادة الفتح.

تظهر المكافأة المتاحة داخل شاشة التحدّي، وتظهر المكافأة الكلية في شاشة النتيجة، وتُحفظ في JSON تحت `speed_bonus` مع أزمنة الأسئلة في `solve_times`.

لكل اسم سجل واحد فقط. يتم تجاهل اختلاف حالة الأحرف والمسافات الزائدة، مثلاً `Ahmed` و` ahmed ` هما الاسم نفسه. تُحتفظ بأفضل نتيجة: الأعلى نقاطاً، ثم الأعلى دقة عند تساوي النقاط، ثم الأقل وقتاً. النتيجة الأقل أو المساوية لا تعيد كتابة الملف؛ الأفضل تستبدل سجل الاسم نفسه. كما يتم دمج الأسماء المتكررة الموجودة في ملف قديم عند تحميله.

اختبار السرعة والأسماء:

```bash
.venv_portal/bin/python test_speed_scores.py
```

## الماوس داخل محرر الكود

- انقر داخل الكود لوضع المؤشر، واسحب لتحديد نص أو عدة أسطر.
- انقر مرتين لتحديد كلمة، أو انقر رقم السطر لتحديد السطر كاملاً.
- الزر الأيمن يعرض Copy وPaste وSelect all. اختصارات Ctrl+C وCtrl+V وCtrl+A وCtrl+X متاحة.
- عجلة الماوس فوق الكود تمرّر أسطر الكود، وعند زيادة عدد الأسطر يظهر شريط تمرير جانبي يمكن سحبه. فوق Output أو Errors تمرّر العجلة محتواهما.
- Enter يحافظ على المسافة البادئة ويزيدها بعد `:` أو `{`. تدعم Shift مع الأسهم تحديد النص.

اختبار التعديلات المطلوبة:

```bash
.venv_portal/bin/python test_requested_updates.py
```

## تحديث التعليقات وتغيير الأسئلة

يمكن أن ينتهي كود C++ وJava بتعليق `//` دون سطر جديد بعده؛ يضع المشغّل أقواس البرنامج في أسطر مستقلة حتى لا يبتلعها التعليق. تبقى الأخطاء الفعلية في الكود ظاهرة.

عند بدء لعبة جديدة تتغيّر مجموعة الأسئلة في كل مرحلة مقارنة بالجولة السابقة، مع الحفاظ على تدرّج الصعوبة. إذا عاد نفس الموضوع تتغيّر قيمه أيضًا. تحفظ اللعبة آخر مجموعة في `data/question_history.json` لتستمر المقارنة بعد إغلاق اللعبة وفتحها. قد تعود موضوعات قديمة في جولات لاحقة لأن بنك الموضوعات محدود. إعادة فتح السؤال أو Reset لا يغيّر السؤال الحالي. يحتاج حفظ التذكّر بين مرات التشغيل إلى صلاحية الكتابة في مجلد البيانات.

اختبار الإصلاح وتغيير الجولات: `python test_round_rotation.py`.


## التحديث البصري ووضع معاينة المشرف

ألوان المراحل: سماوي، بنفسجي، وبرتقالي. تمت إضافة عقد ضوئية ومسح خفيف للمتاهة، حركة لقطع الطاقة، مدارات للبوابات، نبضات عند فتح البوابة، وأثر حركة قصير للاعب. شريط تقدم المرحلة يتحرك بسلاسة. القائمة بسيطة ومتمركزة، ومحرر الكود يميز التعليقات والأرقام وكلمات إضافية في اللغات الثلاث.

| المفتاح | الوظيفة |
|---|---|
| F10 | تشغيل/إيقاف وضع معاينة المشرف، من القائمة أو اللعب |
| Page Down | المرحلة التالية أثناء المعاينة؛ يعود من الثالثة إلى الأولى |
| Page Up | المرحلة السابقة أثناء المعاينة |
| F7 | فتح السؤال الأول للمرحلة مباشرة |
| F8 | فتح السؤال الثاني مباشرة |
| F9 | معاينة إنهاء المرحلة والانتقال التلقائي؛ الثالثة تعود للقائمة |
| F4 | عرض تأثير تفعيل البوابة عند مكان اللاعب |
| F3 | تقليل المؤثرات الحركية الجديدة أو استعادتها |

في وضع المعاينة يتوقف عداد الوقت ومكافأة السرعة، ولا تُحفظ النتيجة في لوحة النتائج. بعد إيقاف المعاينة بـF10 تبقى الجولة الحالية غير مؤهلة للحفظ؛ اضغط PLAY لبدء جولة عادية جديدة. وضع المعاينة محلي بمفتاح، وليس حساب مشرف بكلمة مرور. يظل تشغيل الأسئلة عبر المشغّل المحمي نفسه. لا يمكن التنقل بين المراحل أو الأسئلة أثناء تشغيل كود؛ انتظر انتهاء العملية. بدء جولة معاينة من القائمة لا يغيّر ملف سجل الأسئلة.

التشغيل المعتاد: `bash start.sh`، ثم F10 لمعاينة التعديلات بسرعة. اختبار الواجهة: `python test_visual_preview.py`؛ هذا الاختبار يستخدم نتيجة مرجعية وهمية لفحص الواجهة فقط، ولا يختبر تنفيذ لغات البرمجة. للتأكد من تشغيل اللغات فعليًا استخدم `bash local.sh verify` على جهاز Fedora.

## الرسومات المحسّنة وAdmin دون إعادة بدء

- زر F10 الآن يفعّل/يعطّل Admin في مكانك: لا يغيّر المتاهة أو موقع اللاعب أو المرحلة أو الأسئلة أو القلوب أو النقاط أو مسودة الكود. تظهر فقط رسالة ADMIN ENABLED أو ADMIN DISABLED لوقت قصير. يمكن تفعيله أيضًا أثناء انتظار تشغيل الكود دون إلغاء العملية.
- في القائمة، F10 يغيّر الوضع فقط؛ لا يبدأ جولة. اضغط PLAY عندما تريد اللعب. مفاتيح المراحل Page Up/Page Down هي وحدها التي تطلب تحميل مرحلة أخرى.
- أزيل دليل مفاتيح المشرف الدائم وبطاقات القائمة الجانبية. تبقى القائمة بسيطة: شخصية متحركة، عنوان، PLAY، اختيار لغة، Settings وHigh Scores.
- رسومات جديدة للشخصية في assets/art/robot_stage1.png وحتى robot_stage3.png. كل صورة 512×256، بأربعة اتجاهات في الصفوف: أسفل، يمين، أعلى، يسار، وثمانية إطارات حركة في الأعمدة؛ حجم الإطار 64×64.
- الأرضيات والجدران تُرسم بخامات معدنية مخزنة، وقطع الطاقة بلورات متعددة الأوجه. إضاءة اللاعب تتفاعل مع جدران المتاهة عن طريق تتبع الأشعة؛ التوهّج للبوابات والطاقة خفيف للحفاظ على وضوح اللعب.
- لا توجد مكتبات تشغيل جديدة. الرسوم تستخدم pygame-ce الحالي. لا تتطلب تثبيت Aseprite أو ModernGL، ولم يُنقل المشروع إلى محرك آخر.
- وضع المعاينة لا يحفظ النتائج؛ بعد إيقافه ابدأ جولة جديدة للمنافسة. لم تتغير مفاتيح المعاينة نفسها.

التحقق من عدم إعادة البدء: `python test_admin_state.py`.
