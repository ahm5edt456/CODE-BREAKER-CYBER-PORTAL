# CODE BREAKER: CYBER PORTAL — Campaign

ثلاث مراحل متتالية، في كل مرحلة بوابتان وتحدّيان أصعب من السابق. الواجهة داخل المتاهة والمحرر أصبحت بنفس أسلوب قائمة Cyber Portal، باستخدام pygame-ce وpygame_gui.

## التثبيت والتشغيل

على Fedora / Linux افتح الطرفية داخل مجلد اللعبة:

```bash
bash setup.sh
bash start.sh
```

التثبيت مرة واحدة في بيئة `.venv_portal` مستقلة، ويحتاج إنترنت لتثبيت المكتبات فقط. على Windows شغّل setup.bat أولاً ثم start.bat. تشغيل C++ يتطلب g++، وJava تتطلب javac وjava في PATH.

## الاستكشاف والانتقال بين المراحل

1. تجوّل في المتاهة للوصول إلى التحدّي الأول.
2. بعد حله، انتقل إلى التحدّي الثاني الموجود في منطقة أخرى بعيدة.
3. بمجرد حلّ آخر تحدٍّ تظهر شاشة نجاح قصيرة، ثم تبدأ المرحلة التالية تلقائياً بعد نحو ثانية واحدة. يمكن الضغط على CONTINUE أو Enter لتجاوز الانتظار.
4. لا توجد عودة إلى نقطة البداية، ولا حاجة للوصول إلى مخرج معيّن لإنهاء المرحلة.

تُختار مواقع التحدّيات في مناطق مختلفة بعيداً عن زاوية البداية، مع التحقق من أن التحدّي الأول قابل للوصول دون المرور بالبوابة الثانية، وأن الوصول إلى الثاني ممكن بعد حل الأول. تُحل الأسئلة حسب أرقامها للحفاظ على تدرّج الصعوبة.

بعد آخر تحدٍّ في المرحلة الثالثة تنتهي الحملة بالفوز، وتظهر خانة الاسم لحفظ النتيجة في High Scores. الخسارة أيضاً تعرض خانة الاسم.

لكل مرحلة 120 ثانية. يبدأ عدّاد جديد في المرحلة التالية وتبقى القلوب المتبقية كما هي. الحد الأقصى لزمن اللعب الفعلي ست دقائق، دون احتساب الإيقاف وشاشات الانتقال القصيرة. نفاد الوقت أو القلوب ينهي الحملة.

## تدرّج التحدّيات

- المرحلة 1 / Boot Sequence: العمليات الحسابية، ثم فهرسة القوائم أو المصفوفات.
- المرحلة 2 / Control Flow: حدود الحلقة، ثم تجميع القيم داخل حلقة.
- المرحلة 3 / Core Recovery: الدوال مع الشروط، ثم الحلقات المتداخلة.

يتم تغيير القيم الرقمية عند بدء اللعبة لتوفير تنويعات. يدعم كل تحدٍّ Python وJava وC++ ونوعي Debugging وComplete Code. الأرقام المعروضة للبوابات والتحدّيات متصلة من 1 إلى 6 عبر المراحل.

## الإعدادات

نوع المشكلة فقط: Debugging لإصلاح الخطأ، أو Complete Code لإكمال السطر الناقص، مع خيار تشغيل الصوت أو كتمه. لا يوجد اختيار يدوي للمستوى أو الجولة، ولا يطلب الاسم قبل اللعب.

## الواجهة والتحكم

أُزيلت نقاط التوجيه أمام BYTE وأثر الخلايا التي مرّ عليها. قطع الطاقة الذهبية قابلة للجمع وتضيف 10 نقاط؛ وهي مختلفة عن نقاط التوجيه المحذوفة.

يوجد شريط يوضح المراحل الثلاث، وعدد التحدّيات المكتملة والوقت والقلوب والنقاط. تعرض لوحة المهمة البوابات وحالتها، وتُظهر أن حل آخر تحدٍّ ينقل اللاعب تلقائياً إلى المرحلة التالية. توجد حركة أنعم للشخصية، ونبض للبوابات، وجزيئات عند النجاح، وشاشة انتقال بين المراحل.

- القائمة: الأسهم للتنقل، Enter للاختيار، Tab وShift+Tab للتنقل، Esc للرجوع. الماوس متاح أيضاً.
- اللعب: WASD أو الأسهم للحركة، Space للاندفاعة، E للتحدّي. تفتح نافذة التحدّي تلقائياً عند الاقتراب من بوابة أثناء الحركة.
- P أو Esc أثناء التنقل يفتح الإيقاف المؤقت. زر PAUSE يعمل في المتاهة والمحرر عندما لا يكون الكود قيد التشغيل. لا يُخصم وقت أثناء الإيقاف أو شاشة الانتقال. Enter يستأنف، ويمكن التنقل بين زري الإيقاف بالأسهم أو Tab.
- المحرر: F5 أو Run لتشغيل الكود مجاناً، F6 أو Submit لإرسال الحل. الإرسال الخاطئ يخصم قلباً؛ Run لا يخصم قلباً. F1 للتلميح، Ctrl+R لإعادة الكود، Esc أو Back للرجوع. عجلة الفأرة تمرر الناتج والأخطاء.
- F11 لتبديل ملء الشاشة. يفضل عرض 1280×720 أو أكبر.

## النقاط والاسم

كل حل صحيح: 100 نقطة و25 إضافية إن لم يُستخدم التلميح. الطاقة: 10 نقاط للقطعة، ويضاف الوقت المتبقي عند إنهاء كل مرحلة. النتائج محلية داخل مجلد اللعبة في `data/dashboard.json`. يُنشأ الملف تلقائياً عند التشغيل، وتُحفظ النتيجة بعد كتابة الاسم والضغط على SAVE SCORE، وتُحمّل النتائج عند التشغيل التالي. ينقل التشغيل الأول النتائج القديمة من `~/.code_breaker_ieee/scores.json` إن وُجدت، دون حذف الملف القديم.

بعد نهاية الحملة اكتب الاسم ثم Enter أو SAVE SCORE. الاسم حتى 16 حرفاً، وBackspace للتعديل، وEsc لتخطي الحفظ. لا تُحفظ نتيجة باسم تلقائي، ولا يطلب الاسم بين المراحل.

## ملفات التنفيذ والاختبار

- main.py يشغّل CampaignGame في campaign.py.
- challenge_placement.py يختار مواقع التحدّيات المتباعدة ويتحقق من إمكانية الوصول إليها.
- campaign_questions.py يحتوي التحدّيات الستة وتنويعاتها.
- portal_ui.py يحتوي قائمة Cyber Portal والعناصر المشتركة.
- game.py وengine.py يحتويان منطق اللعب الأساسي.
- assets/theme.json يحدد مظهر عناصر pygame_gui.

بعد التثبيت:

```bash
.venv_portal/bin/python test_campaign.py
.venv_portal/bin/python test_portal.py
.venv_portal/bin/python test_game.py
```

اختُبرت Python وC++ في بيئة التطوير. Java تحتاج إلى تجربة على جهاز فيه JDK. اختبارات الواجهات تستخدم SDL dummy؛ جرّب الصوت وملء الشاشة على جهاز العرض. الصور المرفقة من النسخة الحالية، ولا تتضمن الحزمة نتائج اختبار محفوظة.

التقييم يقارن الناتج الفعلي بالناتج المرجعي، والأسئلة ببيانات ثابتة داخل كل محاولة. التشغيل له مهلة وحدود على العمليات والناتج، لكنه ليس صندوقاً أمنياً لخدمة عامة؛ هذه النسخة للعرض المحلي بإشراف.

## ملف Dashboard JSON

الملف `data/dashboard.json` عبارة عن قائمة JSON تحتوي أعلى 30 نتيجة. كل سجل يتضمن الاسم والنقاط والوقت والدقة واللغة ونوع التحدّي وحالة الفوز والمراحل المكتملة، مع عدد المشكلات المحلولة والمحاولات والطاقة والقلوب المتبقية وتاريخ الحفظ `saved_at` بتوقيت UTC.

الأسماء تدعم UTF-8، بما فيها الأسماء العربية. يتم استبدال الملف بعد اكتمال كتابة النسخة الجديدة، حتى يبقى الحفظ السابق سليماً إذا فشلت الكتابة. إذا كان JSON تالفاً لا يُستبدل بنتائج فارغة؛ أصلح الملف ثم أعد الحفظ. عند تحديث اللعبة أو نقلها، احتفظ بملف `data/dashboard.json` وانقله إلى النسخة الجديدة. يمكن إفراغ لوحة النتائج يدوياً بجعل محتوى الملف `[]` بعد إغلاق اللعبة.

اختبار الحفظ المستقل:

```bash
.venv_portal/bin/python test_score_store.py
```
